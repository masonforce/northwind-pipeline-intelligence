# Northwind Pipeline Intelligence demo

A narrowly-scoped demo for a fictional commercial-card issuer, **Northwind**: a **Pipeline
Intelligence agent** for commercial leaders that pinpoints **where the funnel stalls**, with
drill-downs and contextual insight on the drivers, sourced from **Salesforce via Lakeflow Connect**.
One Genie agent, one governed semantic layer, one app. All data is synthetic.

```
Salesforce (mock Lakeflow Connect tables, incl. OpportunityHistory) + Outreach call export
  -> Lakeflow pipeline (bronze / silver with AI Functions / gold)
  -> 5 UC metric views (pipeline, funnel-stage stall, demand, call signals, campaigns)
  -> 1 Genie agent (Northwind Pipeline Intelligence) + call-transcript volume
  -> Northwind Pipeline Intelligence app (Leader KPIs, Funnel stall, Ask)
       + Lakebase (managed Postgres): serves individual deal records (synced from the gold deal table)
         and takes write-back (saved what-if scenarios, flagged deals)
```

Two tiers: aggregates and trends come from the governed metric views on the lakehouse (SQL warehouse);
individual deal records serve from Lakebase (Postgres point lookup), which also holds the write-back.

## Execution evidence

`evidence/` holds committed text proof that this build ran end to end: a full green `rebuild.sh` log,
`verify.sql` query results, a Lakebase serving + write-back roundtrip, and live Genie model output
(with the governed SQL it generated). See [`evidence/README.md`](evidence/README.md). All data is
synthetic (generated by the scripts here, seed 42); there is no customer data.

## Rebuild from scratch

```bash
DATABRICKS_PROFILE=<your-cli-profile> WAREHOUSE_ID=<your-sql-warehouse-id> ./rebuild.sh
```

Placeholders to replace with your own before running:
- `fe_demo_catalog` (used across the SQL and configs): a Unity Catalog you have CREATE SCHEMA and
  grant rights on. The demo creates the `northwind_pipeline` schema inside it.
- `DATABRICKS_PROFILE` / `WAREHOUSE_ID`: your authenticated CLI profile and a serverless SQL warehouse.

Idempotent. Needs the Databricks CLI (authenticated), python3, and `psql`.

## The story it tells

A leader asks **"where are Northwind Commercial Card deals stalling?"** The semantic layer answers from
Salesforce OpportunityHistory: deals sit longest in the **Solution** stage. Slice that stage and the
driver is **NetSuite / ERP-gap** accounts. Drill into a stalled deal (e.g. **OPP-01042**) and the
call transcript has the prospect's own words: *"our controller would not sign off without a native
NetSuite sync."* Metrics locate the stall; transcripts explain it. The same layer also answers win
rate, loss reasons, the 9/30 launch demand spike, and campaign quality (responses vs pipeline).

## What's here

| File | Purpose |
|---|---|
| `generate_northwind_data.py` | Synthetic Salesforce + marketing + Outreach records (seed 42). Planted findings on purpose. |
| `generate_sfdc_connector_tables.py` | Reshape them into the Lakeflow Connect Salesforce tables (API field names, OpportunityHistory with the planted stall). The governed source. |
| `generate_northwind_docs.py` | Entity-keyed call-transcript PDFs (one per call). |
| `deploy.sql` | Schema and volumes (`landing`, `landing_sfdc`, `call_transcripts`). |
| `pipeline/` | Lakeflow Spark Declarative Pipeline (serverless): bronze reads the connector tables, silver maps the Salesforce shape to the Northwind model + AI Functions on transcripts, gold adds the funnel-stage dwell fact. |
| `deploy_metric_views.sql`, `verify.sql` | The 5 metric views (incl. `funnel_stage_metrics`), plus checks of the planted findings. |
| `deploy_functions.sql` | `northwind_documents(id)` / `northwind_search_documents(phrase)` over the parsed transcripts. |
| `deploy_genie_agents.py` | Creates/updates the single **Northwind Pipeline Intelligence** Genie agent. |
| `app/` | The Databricks App (Leader, Funnel, Ask). Reads aggregates from the metric views + transcripts from the volume, serves the individual deal card from Lakebase, and writes back to Lakebase (saved what-if scenarios, flagged deals). |
| `deploy_serving.sql` | Builds `gold_serving_deals` (one row per deal, PK `opportunity_id`), the source synced to Lakebase `deals_online`. |
| `lakebase.sql` | App-state tables in Lakebase (`saved_scenarios`, `deal_followups`) and grants to the app service principal. |
| `run_sql.py` | Runs a .sql file on the warehouse. |
| `claude-demo/` | Contained Claude Code demo: `start-demo.sh` connects Claude to the Genie agent, the `northwind-documents` functions and Genie One over MCP. |

## Known limits
- The Genie Conversation API and per-agent MCP answer from the metric views only; they do not read
  the attached volume. Transcripts come through the `northwind-documents` UC functions (and the app's own
  document panel). This is why the agent pairs with the functions MCP in `claude-demo/`.
- Salesforce arrives as CSVs mocking the Lakeflow Connect destination. In production the managed
  connector writes the same tables (same API field names) as streaming tables; `pipeline/` reads them
  the same way.
- `generate_northwind_docs.py` imports the dependency-free PDF writer from the local `pdf_writer.py`.
